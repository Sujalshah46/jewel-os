# ADR-001: authenticated tenant customer slice

- **Status:** Implemented for the bounded customer API; broader ERP migration is pending.
- **Context:** The application had only React and browser localStorage. No server authority existed for identity, role, tenant ownership, writes, or recovery.
- **Decision:** Use Better Auth for email/password identity and opaque, database-backed, HTTP-only same-site sessions. Use PostgreSQL as the authoritative relational store and Drizzle ORM/Kit for schemas and versioned SQL migrations. Keep customer persistence in parameterized PostgreSQL queries whose every read/update predicate includes the server-derived tenant ID. Treat `X-Tenant-Id` only as a requested membership selection, never as an authority claim. Store tenant roles in `membership`; keep platform grants in a separate table and do not let platform authority imply tenant ownership.
- **Cookie/write protection:** `SameSite=Lax`, `HttpOnly`, `Secure` on HTTPS; Better Auth trusted origin validation; custom customer mutations require a per-session HMAC CSRF token and same-origin Origin/Referer validation. The API has no permissive CORS policy. Session cookie caching is disabled so expiry, deletion, and membership-disable changes are observed on requests.
- **Account creation:** Public sign-up is disabled in the operational server. `npm run operator:provision` is a local, one-shot operator command which provisions an owner and tenant from environment variables; it does not run an HTTP server.
- **Demo boundary:** `VITE_APP_MODE=demo` loads the legacy application; `VITE_APP_MODE=operational` dynamically loads a standalone server-backed customer UI. Operational UI code does not import the legacy provider, seeds, localStorage, billing or integrations. There is no cross-mode import or automatic local data migration.
- **Consequences:** PostgreSQL and a strong `BETTER_AUTH_SECRET` are mandatory for operational mode. New user passwords are processed by Better Auth; this repository does not implement password hashing. Operational deployment must host the API and same-origin UI together (or provide an explicitly configured same-origin reverse proxy). Existing static Vercel config remains demo-only.
- **Alternatives:** A hand-built password/session stack was rejected. Prisma was briefly evaluated but its native schema-engine checksum host returned 403 in this environment; checksum checks were not bypassed. Drizzle produces SQL migrations without the blocked native download and is adequate for the requested relational slice.
